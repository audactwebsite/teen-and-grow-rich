## What each rule checked

| Rule | What it measured |
| --- | --- |
| `img-alt` | Every `<img>` has an `alt` attribute. An empty `alt` is correct for a decorative image and is not counted. |
| `control-name` | Every input, select and textarea has a label, `aria-label`, `aria-labelledby` or `title`. |
| `heading-skip` | No heading level is skipped, so the outline a screen reader navigates by stays intact. |
| `h1-count` | Exactly one `<h1>` per page. |
| `duplicate-id` | No id appears twice, which would break `aria-labelledby` and in-page anchors. |
| `target-size` | WCAG 2.2 AA 2.5.8: interactive targets at least 24×24 CSS px. Targets inside a line of prose are exempt and are skipped. |
| `landmark` | A `<main>` element exists. |
| `lang` | `<html>` carries a language. |
| `overflow-320` | Nothing scrolls sideways at a 320px viewport. |
| `external-host` | No request goes to any host but this one. |

Two real defects were found by this run and fixed before it was written down.

**`frame-ancestors` in a `<meta>` CSP.** The CSP spec requires browsers to ignore that
directive when it arrives in a meta element, so it protected nothing and logged a console
error on every page load — the only failing Lighthouse item on the homepage. It is now a
real `Content-Security-Policy` response header from `vercel.json`, alongside
`X-Frame-Options: DENY`, and is gone from the meta policy where it could never work.

**0.255 cumulative layout shift on every page of the site.** At 390px the header's three
items came to about eight pixels more than the available width while the metric-adjusted
fallback font was still in use, so the header shipped two rows tall and unwrapped to one
the moment Noto Sans arrived — the theme toggle jumping from (20, 50) to (251, 10) and
everything below it moving up 41px. It surfaced on /receipts, which made it look like a
receipts problem; it was a header problem, on all 147 pages, in the first thing anybody
sees. The header is now deterministic at every width — two rows below 26rem on purpose,
one row above.

## Still not tested

Listed here so a page of green is not read as a clean bill of health it did not earn:

- **axe-core has not been run.** Lighthouse's accessibility category uses a subset of axe
  rules. It is not the same thing as a full axe pass.
- **No screen reader session** with somebody who uses one daily — not NVDA, not JAWS, not
  VoiceOver, not with a real user rather than a developer.
- **No recorded keyboard-only pass** of the worksheets, timers, checklists and the
  page-number field, step by step.
- **No 200% or 400% zoom check** across every template.
- **No forced-colours or Windows High Contrast test.**
- **No voice control test.**

A Lighthouse accessibility score of 100 means no automated rule fired. It does not mean the
site works for a disabled reader, and this project is not going to imply otherwise. The
same list is on /accessibility.
